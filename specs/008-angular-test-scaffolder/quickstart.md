# Quickstart Validation Guide: Angular Test Scaffolder

**Feature**: 008-angular-test-scaffolder
**Created**: 2026-07-09

This guide describes how to validate that the test scaffolder change in `coder-angular-frontend.md` works correctly.

---

## Prerequisites

| Requirement | Check Command |
|---|---|
| Node.js ≥ 18 | `node -v` |
| Angular CLI ≥ 17 | `ng version` |
| A project generated by `ava-stack-angular-frontend` | `ls projects/{PROJECT_NAME}/outputs/tobe/source-code/frontend/` |
| Chrome/Chromium (for Karma headless) | `google-chrome --version` OR set `CHROME_BIN=chromium` |

---

## Scenario 1 — Spec Files Are Generated (PBI 2284 + 2285)

**Purpose**: Verify the agent generates `*.spec.ts` files alongside source files.

**Setup**: Invoke `@ava-stack-angular-frontend` on a project with at least one Service, one Guard, one Interceptor, and one Pipe.

**Validation commands**:
```bash
# From the project root
BASE=projects/{PROJECT_NAME}/outputs/tobe/source-code/frontend/src/app

# Services
find $BASE -name "*.service.ts" ! -name "*.spec.ts" | while read f; do
  spec="${f%.service.ts}.service.spec.ts"
  [ -f "$spec" ] && echo "✅ $spec" || echo "❌ MISSING: $spec"
done

# Guards
find $BASE -name "*.guard.ts" ! -name "*.spec.ts" | while read f; do
  spec="${f%.guard.ts}.guard.spec.ts"
  [ -f "$spec" ] && echo "✅ $spec" || echo "❌ MISSING: $spec"
done

# Interceptors
find $BASE -name "*.interceptor.ts" ! -name "*.spec.ts" | while read f; do
  spec="${f%.interceptor.ts}.interceptor.spec.ts"
  [ -f "$spec" ] && echo "✅ $spec" || echo "❌ MISSING: $spec"
done

# Pipes
find $BASE -name "*.pipe.ts" ! -name "*.spec.ts" | while read f; do
  spec="${f%.pipe.ts}.pipe.spec.ts"
  [ -f "$spec" ] && echo "✅ $spec" || echo "❌ MISSING: $spec"
done
```

**Expected outcome**: Every `*.ts` source file has a corresponding `*.spec.ts`. No `❌ MISSING` lines.

## Scenario 2 — Coverage Threshold in angular.json (PBI 2286)

**Purpose**: Verify the generated `angular.json` includes coverage threshold configuration.

**Validation command**:
```bash
cat projects/{PROJECT_NAME}/outputs/tobe/source-code/frontend/angular.json \
  | python3 -c "
import sys, json
d = json.load(sys.stdin)
proj = list(d['projects'].values())[0]
opts = proj['architect']['test']['options']
thresh = opts.get('coverageThreshold', {})
assert opts.get('codeCoverage') == True, 'codeCoverage not set'
assert thresh.get('statements') >= 80, 'statements threshold < 80'
assert thresh.get('branches') >= 80, 'branches threshold < 80'
assert thresh.get('functions') >= 80, 'functions threshold < 80'
assert thresh.get('lines') >= 80, 'lines threshold < 80'
print('✅ angular.json coverage threshold OK')
"
```

**Expected outcome**: `✅ angular.json coverage threshold OK`

## Scenario 3 — Tests Compile and Pass (PBI 2287)

**Purpose**: Run `ng test` in a generated project and confirm zero compilation errors.

**Validation commands**:
```bash
cd projects/{PROJECT_NAME}/outputs/tobe/source-code/frontend
npm install
ng test --no-watch --code-coverage --browsers ChromeHeadless
```

**Expected outcome**:
- Exit code `0`
- No `TS2305`, `TS2307`, or `TS2304` TypeScript compilation errors in spec files
- Coverage report generated at `coverage/`
- Console output: `X specs, 0 failures`

**If tests fail**:
- `Cannot find module '@angular/common/http/testing'` → check `@angular/common` version matches `@angular/core`
- `MsalService is not provided` → stub not registered in `providers`
- Coverage threshold error → check `angular.json` `coverageThreshold` was applied

## Scenario 4 — Routing Guard Bypass (pipeline_mode = build-cycle)

**Purpose**: Confirm the existing routing guard still fires and no spec files are generated.

**Validation**: Set `pipeline_mode: build-cycle` in `project-config.yaml` and invoke the agent. Confirm it emits the routing guard message and exits without writing any `*.spec.ts` files.

**Expected outcome**: Agent output contains `⛔ ROTEAMENTO: Este projeto usa pipeline_mode = "build-cycle"` and no new files are written.
