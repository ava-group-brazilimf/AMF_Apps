## 1. Overview

Three agents are being discontinued from the F1 AS-IS diagnostic pipeline:

| Agent ID | Agent file | Skill wrapper |
|---|---|---|
| `ava-asis-test-qa` | `test-qa-asis.md` | `.github/skills/ava-asis-test-qa/SKILL.md` |

- 2 root documentation files (`README.md`, `.github/copilot-instructions.md`)

## 4. User Scenarios (Given-When-Then)

### Scenario 1 — Nominal: pipeline runs without discontinued agents (Priority: P1)

**Story**: Como orchestrator, quero que o pipeline AS-IS conclua sem tentar despachar os agentes removidos, para que não haja erros de dispatch ou artefatos esperados ausentes.

**Acceptance Scenarios**:

1. **Given** `orchestrator-asis.md` with the changes from §3.1 applied, **When** an SA or FP trigger runs, **Then** no dispatch for `ava-asis-test-qa`, `ava-asis-baseline-test-generator`, or `ava-asis-golden-dataset-capture` occurs.
2. **Given** the above, **Then** Phase A Wave 2 dispatches exactly 5 agents: `inventory`, `db-analyzer`, `events-pubsub`, `doc:FT`, `doc:VC`.
3. **Given** the above, **Then** the Consistency Gate contains no C2c check and no `ARTIFACT-COMPLETE-GOLDEN-DATASET` block.

### Scenario 2 — Summary pipeline runs without removed artifact paths (Priority: P1)

**Story**: Como agente `ava-summary`, quero que os dados de test coverage venham de `09_test_coverage.json` (Delphi) e `test-gaps.md`, sem tentar ler arquivos que não existem mais.

**Acceptance Scenarios**:

1. **Given** `summary-agent.md` with changes from §3.12 applied, **When** the summary pipeline runs for a Delphi project, **Then** test coverage data is read from `delphi-ast-raw/compressed/09_test_coverage.json`.
2. **Given** the above for a non-Delphi project, **Then** `testMap` resolves to `[AUSENTE]` without error.
3. **Given** `validate_summary.py` with changes from §3.17 applied, **When** the Test Gaps section is empty, **Then** the error message references `test-gaps.md · 09_test_coverage.json` only.

### Scenario 3 — No broken references in documentation (Priority: P2)

**Story**: Como desenvolvedor lendo a documentação do projeto, não quero encontrar referências a agentes que não existem mais no pipeline.

**Acceptance Scenarios**:

1. **Given** all documentation files updated per §3.4–3.11, **When** searching for `ava-asis-test-qa`, `ava-asis-baseline-test-generator`, or `ava-asis-golden-dataset-capture`, **Then** no matches are found in any active pipeline documentation or configuration file.
2. **Given** the above, **When** searching for `golden_dataset_enabled_asis`, **Then** no matches are found.

### Scenario 4 — bridge-fastqa produces test-gaps.md (Priority: P1)

**Story**: Como agente `ava-summary` e fases downstream, quero que `test-gaps.md` continue sendo gerado no mesmo path `outputs/asis/qa/`, agora produzido por `ava-asis-bridge-fastqa` Step 15.

**Acceptance Scenarios**:

1. **Given** `bridge-fastqa-asis.md` with changes from §3.18 applied and a PBI with gap analysis available, **When** Step 15 runs, **Then** `projects/{project_name}/outputs/asis/qa/test-gaps.md` is created with at least one `TG-NNN` row.
2. **Given** the above, **When** the gap_analysis source (`PBI-{N}_gaps.md`) is absent, **Then** a warning is emitted and `test-gaps.md` is not created — the pipeline does not halt.
3. **Given** `orchestrator-asis.md` `artifact_contracts` updated per §3.1.6, **When** `verify_artifacts("ava-asis-bridge-fastqa")` runs, **Then** it checks for `qa/test-gaps.md` in addition to `qa/test-plan.md`.

Adding `test-gaps.md` to that step is a minimal extension of existing logic — it does not require a new agent or a new dispatch in the orchestrator DAG.
- `delphi-ast-raw/compressed/09_test_coverage.json` already exists as a reliable source for test coverage data in Delphi projects (produced by `ava-asis-solution-delphi` Step 0 AST extraction).
- No other agents outside the 18 listed files consume `test-map.md`, `test-baseline.md`, `test-coverage-asis.md`, `test-cases-baseline-asis.*`, or `golden-dataset.*` as inputs.
