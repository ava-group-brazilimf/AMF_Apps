# Implementation Plan: Partial Modernization Support — Strangler Fig Pattern

**Branch**: `008-partial-modernization-support` | **Date**: 2026-07-09 | **Spec**: [spec.md](spec.md)

**PBI**: 2316 | **Child PBIs**: 2317, 2318, 2319, 2320, 2321

---

## Summary

Add Strangler Fig partial-modernization support to the IMFAI pipeline through
configuration-driven routing. Two new fields in `project-config.yaml`
(`modernization_scope` and `target_modules`) control whether the
master-orchestrator dispatches `ava-tobe-coexistence-strategy` before F1 and
whether the stack-orchestrator limits code generation to named bounded contexts.
No new agent files. Five existing files modified. Fully backward-compatible
(`modernization_scope` defaults to `"full"` when absent).

## Implementation Phases

### Phase 1 — Config Schema

**File**: `projects/_template/context/project-config.yaml`

**Insertion point**: After `scope_modules: "all"` line.

**Child PBI**: 2317

```yaml
scope_modules: "all"                    # "all" ou lista: ["financeiro", "cadastro"]

# ─────────────────────────────────────────────────────────────────────────────
# Modernização Parcial (Strangler Fig Pattern)
# Controla se o pipeline moderniza todos os BCs ou apenas um subconjunto.
# ─────────────────────────────────────────────────────────────────────────────
#
# modernization_scope: Escopo da modernização.
#   "full"    → Pipeline completo F1→F2→F3→F5→F7→F6 (padrão).
#               Todos os bounded contexts em scope_modules são processados.
#   "partial" → Modernização incremental via Strangler Fig pattern.
#               Apenas os BCs em target_modules são migrados.
#               Ativa: coexistence-strategy ANTES de F2 (passo 0.5).
modernization_scope: "full"
#
# target_modules: Lista de BCs a modernizar (usado quando modernization_scope = "partial").
#   Formato: lista YAML de strings com os IDs dos BCs (devem estar em scope_modules).
#   Exemplo: ["financeiro", "cadastro"]
#   Ignorado quando modernization_scope = "full".
target_modules: []
```

#### 2a.2 — Step 0 pre-flight: add steps 0.4 / 0.4a / 0.4b

Append after the existing `0.3 EXTRACT configuração de pipeline` block
in `## Execution Steps → Step 0`:

```
0.4  READ modernization_scope (padrão: "full") e target_modules (padrão: [])
     → Se modernization_scope == "partial":
         Se target_modules está vazio → EMITIR bloco PARTIAL PRE-FLIGHT com DECISION: BLOCKED
         Mensagem: "modernization_scope=partial requer target_modules não-vazio."
         PARAR — nenhum agente despachado
0.4a SE scope == "partial" AND target_modules não-vazio:
       EMITIR bloco PARTIAL PRE-FLIGHT com DECISION: PROCEED
       Registrar: partial_mode = true; filtered_bcs = target_modules
0.4b SE scope == "full" AND target_modules não-vazio:
       LOG WARN: "target_modules ignorado: modernization_scope=full processa todos os BCs."
       Continuar normalmente (partial_mode = false)
```

**Pre-flight block template** (emitido quando `scope=partial`):

```
╔══════════════════════════════════════════════════════════════════════╗
║  PARTIAL MODERNIZATION MODE — PRE-FLIGHT                            ║
╠══════════════════════════════════════════════════════════════════════╣
║  modernization_scope: partial                                       ║
║  target_modules: {list}                                             ║
║  coexistence-strategy: [executará no passo 0.5]                    ║
╠══════════════════════════════════════════════════════════════════════╣
║  DECISION: [PROCEED | BLOCKED]                                      ║
╚══════════════════════════════════════════════════════════════════════╝
```

**File**: `src/modules/ava-fabric-agents/tech-stack/agents/orchestrator-stack.md`

**Child PBI**: 2319

#### 2b.1 — Frontmatter version bump

```yaml

# AFTER

```

#### 2b.2 — Step 0 pre-flight: add step 0.4 with BC filter guard

Append after the existing `0.3b RESOLVE agent roster` block:

```
0.4  READ modernization_scope e target_modules de project-config.yaml
     Se modernization_scope == "partial" AND target_modules não-vazio:
       filtered_bcs = target_modules
       LOG: "⚙ Modo parcial: codegen limitado a BCs → {filtered_bcs}"
     Senão:
       filtered_bcs = null  # sem filtragem — todos os BCs processados
```

Then, before the first BC dispatch in the execution sequence, add the guard block:

```
[BC FILTER CHECK — executado apenas quando filtered_bcs != null]
Para cada bc_id na fila de codegen:
  SE bc_id NÃO está em filtered_bcs:
    → LOG: "⏭ BC '{bc_id}' fora de target_modules — ignorado."
    → REMOVER bc_id da fila
  SENÃO:
    → Manter na fila

EMITIR tabela de BCs filtrados antes do primeiro dispatch:
| BC ID | Em target_modules? | Ação |
|-------|-------------------|------|
| {id}  | ✅ / ❌          | Codegen despachado / Ignorado |
```
