## 4. Problem Statement

### Context

The `ava-tobe-orchestrator` enforces **three places** in `orchestrator-tobe.md` that require `master-report.md` to exist before proceeding:

| Location | Line (approx.) | Behavior |
|---|---|---|
| `## ADR-First Protocol` → Fase 0-Pre | ~145 | Lists `master-report.md` as mandatory pre-condition |
| Trigger table — SD gate | ~1495 | Hard BLOCKED if file absent |
| `## Reasoning Approach` — step 1 | ~1810 | Hard PARAR IMEDIATAMENTE if file absent |

### Root Cause

The `master-report.md` is a consolidated summary produced by `ava-asis-orchestrator` at the **end** of the AS-IS phase. It is not always generated when users run individual AS-IS sub-agents or when the AS-IS diagnostic is partial. The other AS-IS artifacts (`bounded-context-map.md`, `architecture-blueprint.md`, `db-analysis-report.md`, `gaps-risks/`, `docs/`) are present and sufficient for the TO-BE pipeline to function.

The gate should therefore be **downgraded**: the absence of `master-report.md` should emit a **warning** (not a hard BLOCKED), allow the pipeline to proceed using the other available AS-IS artifacts, and suggest generating the consolidated report if desired.

## 5. User Scenarios (Given-When-Then)

### Scenario 1 — Nominal: SD trigger with all AS-IS artifacts except master-report.md (Priority: P0)

**Story**: Como orquestrador TO-BE, quero iniciar o design quando `master-report.md` estiver ausente mas os demais artefatos AS-IS estiverem presentes, para não bloquear a esteira.

**Acceptance Scenarios**:

1. **Given** `projects/{project_name}/outputs/asis/master-report.md` does NOT exist AND `bounded-context-map.md`, `architecture-blueprint.md`, `db-analysis-report.md` DO exist, **When** the SD trigger fires, **Then** the orchestrator emits a `[AVISO]` warning about the absent `master-report.md` and **proceeds** to Fase 0-Pre normally.
2. **Given** the above, **When** the pipeline completes, **Then** no BLOCKED or PARAR IMEDIATAMENTE message appears in the output.
3. **Given** the above, **Then** a suggestion to run `@ava-asis-orchestrator trigger: SR` to generate the consolidated report is included in the warning output.

---

### Scenario 2 — Nominal: SD trigger with master-report.md present (Priority: P1)

**Story**: Como orquestrador TO-BE, quero continuar funcionando normalmente quando `master-report.md` estiver presente.

**Acceptance Scenarios**:

1. **Given** `master-report.md` exists, **When** the SD trigger fires, **Then** the orchestrator proceeds with no warning and no change to existing behavior.

---

### Scenario 3 — Edge Case: No AS-IS artifacts at all (Priority: P1)

**Story**: Como orquestrador TO-BE, quero bloquear somente quando os artefatos essenciais do AS-IS também estiverem ausentes, não apenas o master-report.md.

**Acceptance Scenarios**:

1. **Given** neither `master-report.md` NOR `bounded-context-map.md` NOR `architecture-blueprint.md` exist, **When** the SD trigger fires, **Then** the orchestrator emits a **BLOCKED** gate referencing the missing essential artifacts (not specifically `master-report.md`).
2. **Given** the above, **Then** the message guides the user to execute the full AS-IS diagnostic first.

## 6. Proposed Implementation

### 6.1 Changes to `orchestrator-tobe.md`

Three targeted edits to the agent body:

#### Edit 1 — Fase 0-Pre pre-condition (line ~145)

**Before**:
```
- **Pré-condição**: outputs AS-IS concluídos (`master-report.md`, `bounded-context-map.md`, `gaps-risks-report.md`)
```

**After**:
```
- **Pré-condição**: outputs AS-IS essenciais presentes — `bounded-context-map.md`, `architecture-blueprint.md`, `db-analysis-report.md` (ver lista em Fase 0-Pre gate); `master-report.md` é opcional — se ausente, emitir `[AVISO]` e prosseguir
```

---

#### Edit 2 — Trigger table SD gate (line ~1495)

**Before**:
```
> ⛔ **[SD] Gate Obrigatório — AS-IS Master Report**: Antes de qualquer execução do trigger `SD`, verificar se `projects/{project_name}/outputs/asis/master-report.md` existe. Se não existir → **PARAR IMEDIATAMENTE** com a mensagem:
> `[GATE FAILED] AS-IS Master Report não encontrado. Execute o diagnóstico AS-IS (F1) antes de iniciar o design TO-BE`
```

**After**:
```
> ⚠️ **[SD] Verificação Opcional — AS-IS Master Report**: Antes de executar o trigger `SD`, verificar se `projects/{project_name}/outputs/asis/master-report.md` existe. Se não existir → emitir **aviso** (não bloqueante):
> `[AVISO] master-report.md não encontrado. O pipeline TO-BE prosseguirá usando os demais artefatos AS-IS disponíveis. Para gerar o relatório consolidado, execute: @ava-asis-orchestrator trigger: SR`
> O pipeline **não é interrompido**. Verificar presença dos artefatos essenciais do AS-IS (bounded-context-map.md, architecture-blueprint.md, db-analysis-report.md) e prosseguir.
```

---

#### Edit 3 — Reasoning Approach step 1 (line ~1810)

**Before**:
```
1. **Validate** — **[GATE OBRIGATÓRIO — apenas trigger `SD`]** verificar se `projects/{project_name}/outputs/asis/master-report.md` existe; SE não existir → **PARAR IMEDIATAMENTE** com a mensagem: `[GATE FAILED] AS-IS Master Report não encontrado. Execute o diagnóstico AS-IS (F1) antes de iniciar o design TO-BE`; ler `timing_benchmark_enabled`...
```

**After**:
```
1. **Validate** — **[VERIFICAÇÃO OPCIONAL — apenas trigger `SD`]** verificar se `projects/{project_name}/outputs/asis/master-report.md` existe; SE não existir → emitir `[AVISO] master-report.md ausente — pipeline TO-BE prosseguirá com artefatos AS-IS disponíveis` e **NÃO interromper** (não PARAR); verificar artefatos essenciais (`bounded-context-map.md`, `architecture-blueprint.md`, `db-analysis-report.md`) — se todos ausentes → **PARAR IMEDIATAMENTE** com `[GATE FAILED] Artefatos essenciais do AS-IS não encontrados. Execute @ava-asis-orchestrator antes de iniciar o design TO-BE`; ler `timing_benchmark_enabled`...
```

## 10. Assumptions

- The essential AS-IS artifacts (`bounded-context-map.md`, `architecture-blueprint.md`, `db-analysis-report.md`) provide sufficient context for the TO-BE pipeline to function without `master-report.md`.
- `master-report.md` is a convenience summary that aggregates other artifacts — its absence does not indicate an incomplete AS-IS analysis if the individual artifacts are present.
- The `artifact-only-consumption-protocol.md` §2.2 escalation note in the trigger table references `master-report.md` specifically; the note should be retained but its blocking behavior removed.
