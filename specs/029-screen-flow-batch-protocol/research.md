## 1. Root Cause Analysis

### Reported Bug
- `screen-flow.mmd`: **1.8% coverage** on `processaERP-001` (12 of ~665 forms)
- Agent **did not execute** `gen_screen_flow.py` (REGRA ABSOLUTA violated)
- Agent generated mermaid inline using LLM "hallucination" of typical ERP Delphi patterns

### Why the Agent Failed
1. **Context window pressure**: F1 had consumed ~80K tokens; LLM was near output-token limit (~8K)
2. **Tool-call non-compliance**: LLM "knew" it should run the script but chose inline generation as a lower-token-cost path
3. **No assertion barrier**: Post-generation step had no automated check for coverage completeness — 12/665 passed silently

### Existing Tool Analysis — `src/shared/tools/gen_screen_flow.py`

**Already implements the batch protocol proposed in the bug report:**

| Feature | Already in `gen_screen_flow.py`? |
|---|---|
| Read `form-registry.json` via `--input` | ✅ Yes |
| Read `bounded-context-map.md` via `--bc-map` | ✅ Yes |
| Classify forms by BC (exact match → token match → directory fallback) | ✅ Yes |
| Generate `screen-flow.mmd` overview | ✅ Yes |
| Generate per-BC detail files (`screen-flow-{bc}.mmd`) | ✅ Yes |
| Split large BCs into parts (`-p1`, `-p2`) if > 120 items | ✅ Yes |
| Validate every `.mmd` with `validate_diagram.py` | ✅ Yes |
| Output directory creation | ✅ Yes |

**Conclusion**: The tool infrastructure is ready. The fix is **purely agent instruction compliance** — the agent must be told (in unavoidable terms) that it MUST invoke the script and MUST run the assertion.

## 2. Decision Log

| # | Decision | Rationale | Alternatives Rejected |
|---|---|---|---|
| 1 | **Re-use** `gen_screen_flow.py` — do not rewrite it | Already does per-BC generation, validation, splitting. Rewriting = wasted effort. | Rewriting in agent instructions inline — rejected (this is the root cause of the bug) |
| 2 | **80% coverage threshold** for PASS | Realistic given orphan forms, unclassified BCs, and noise in legacy registries. 100% would be brittle and trigger false failures. | 90% — too strict for legacy systems with incomplete metadata. 50% — too lax, would allow significant truncation. |
| 3 | **80 forms = batch protocol trigger** | Single-pass generation of 80 forms fits comfortably within ~8K output tokens (~50 tokens/form × 80 = 4K). Above this, token truncation risk becomes material. | Fixed at 50 — too conservative for medium projects. Always batch — unnecessary overhead for small projects. |
| 4 | **3 retry attempts** before human gate | Matches existing `RetryProtocol` used across all IMFAI agents (max 3 retries per artifact). Consistent with orchestrator behavior. | 1 retry — insufficient for transient issues. 5 retries — wastes tokens; 3 is the project standard. |
| 5 | **`screen-flow-completeness.json` as assertion artifact** | Machine-readable, lightweight, consumable by Summary Validator and QA agents. Extensible for future assertions. | Inline log only — rejected because downstream validators need structured data. |
| 6 | **Retain per-BC intermediate `.mmd` files** | They are already generated by `gen_screen_flow.py` and serve as debugging evidence when assertion FAILs. | Delete intermediates after merge — rejected because they help diagnose missing forms. |

## 4. Risks & Mitigations Identified During Research

| Risk | Likelihood | Impact | Mitigation |
|---|---|---|---|
| `gen_screen_flow.py` path changes in future refactor | Low | High (breaks agent) | Agent instructions use relative path anchored to repo root; path is stable |
| `form-registry.json` missing `bounded_context` field | Medium | Medium (batch protocol falls back to "Unclassified") | Agent instructions include fallback: use `unit_path`/`directory` for BC inference; if all else fails, "Unclassified" becomes its own batch |
| Very large BC (>120 forms) generates multiple parts | Low | Low | `gen_screen_flow.py` already handles this transparently; assertion counts nodes across all parts |
| Validator (`validate_diagram.py`) rejects valid but complex diagram | Low | Medium | Validator return codes 0 and 2 are both treated as PASS in `gen_screen_flow.py`; agent follows same rule |
