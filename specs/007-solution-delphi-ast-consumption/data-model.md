# Data Model: Delphi AST Extraction Artifacts

All 8 files share a common envelope, verified against a real sample run at
`projects/Meu-ERP-006-AST-LLM/outputs/asis/delphi-ast-raw/extraction/`
(generated by the external `ava-fabric-delphi-analyzer` tool, `run_id: 23bd21e334da`,
against `source_root: C:\Desenv\Meu-ERP`).

## Common Envelope

```json
{
  "artifact": "<name matching filename stem>",
  "schema_version": "0.1.0",
  "project": "AVA Fabric - Legacy Delphi Migration",
  "description": "<human description>",
  "payload": { "...": "artifact-specific, see below" },
  "_volatile": {
    "generated_at": "<ISO8601>",
    "run_id": "<hex>",
    "analyzer": "delphi_ast_analyzer/0.1.0",
    "source_root": "<absolute path to Delphi repo>"
  }
}
```

`_volatile` is deliberately isolated at the end (per the external tool's own
docs — keeps a stable prefix for downstream caching).

## 1. `01_business_rules.json`

`payload.counts{total, by_type{calculation: N}, mode}`,
`payload.rules[]` — each: `{type: "calculation", unit, method, target, expression, source_ref: {file, line}, id: "BR-NNNN"}`.

## 2. `02_form_business_rules.json`

`payload.counts{forms, fields}`, `payload.forms[]` — each:
`{form_name, form_class, source_file, field_count, fields[]}`; each field:
`{name, component_class, properties: {...}, event_handlers: {...}, has_validation: bool}`.

## 3. `03_database_rules.json`

`payload.counts{total, mode}`, `payload.rules[]` — each:
`{type: "write_operation", operation: "insert"|"update"|"delete", tables: [...], source_ref: {file, line}, id: "DBR-NNNN"}`.

## 4. `04_database_schemas.json`

`payload.counts{tables_ddl, tables_inferred, datasets, mode}`,
`payload.tables[]` (DDL-derived), `payload.inferred_tables[]` — each:
`{name, origin: "inferred_from_sql", accessed_columns[], operations[], used_in[]}`,
`payload.db_component_datasets[]` — each: `{unit, components[]}` (e.g.
`TADOCommand`/`TADOQuery`/`TADOTable`), `payload.dataset_fields[]` — each:
`{dataset, fields: [{name, delphi_type}]}`.

## 5. `05_procedures.json`

`payload.counts{code_procedures, stored_procedures, mode}`,
`payload.code_procedures[]` — each: `{unit, class, name, kind: "constructor"|"destructor"|"function"|"procedure", params: [...], returns, loc, calls: [...], source_ref: {file, line}}`,
`payload.stored_procedures[]` (DB-side, empty for desktop-only apps).

## 6. `06_integrations.json`

`payload.counts{total, by_type{...}, mode}`, `payload.integrations[]` —
each: `{type, target, via, source_ref: {file}, id: "INT-NNNN"}`.

## 7. `07_apis.json`

`payload.counts{total, mode, note}`, `payload.apis[]` (empty when no HTTP
client detected — `note` field explains why).

## 8. `08_code_overview.json`

`payload.totals{units_parsed_ast, loc_total, classes, procedures, functions, forms_screens, input_fields, avg_cyclomatic, units_total, business_rules, integrations, apis, db_tables, mode}`,
`payload.classes[]` — each: `{name, parent, line, file}` (this is exactly
the `ClassRegistry[]` schema `solution-delphi.md` already expects, and the
basis for the redesigned Step 1 inventory derivation in this PBI),
`payload.complexity_by_unit[]` — each: `{unit, cyclomatic, methods}`.

## Compressed variants (`compressed/`)

Mirror `extraction/` 1:1 (post-`headroom-ai` compression, or a no-op
`router:noop` transform if that optional package isn't installed). Plus two
extra files:

- `manifest.json` — `{engine, model, artifacts: [{artifact, mode, tokens_in, tokens_out, reduction_pct, transforms[]}], totals: {tokens_in, tokens_out, reduction_pct}}`
- `metrics.jsonl` — one line: `{run_id, exec_date, source_root, ast_mode, engine, extraction_duration_ms, precompress_duration_ms, tokens_in, tokens_out, reduction_pct, artifact_counts{...}, status: "ok"}`

## Storage location

```
projects/{project_name}/outputs/asis/delphi-ast-raw/
├── extraction/          ← 8 JSON files (source of truth for this PBI)
├── compressed/          ← same 8 + manifest.json + metrics.jsonl
└── run_delphi_ast_analysis.log
```

## New artifact introduced by this PBI

`asis/code-business-rules.md` — human-readable rendering of
`BusinessRuleRegistry[]` (built from `01_business_rules.json.payload.rules[]`
in Step 3), written alongside diagram outputs in Step 14. Distinct from
`asis/docs/business-rules.md` (produced by `ava-asis-documentation` from
doc-mining, unrelated source).
